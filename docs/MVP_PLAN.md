## 0. ГЛАВНЫЙ РАЗВОРОТ (читать первым)
Экзамен **11.06.2026**, сегодня 31.05 → **≈11 дней**. За 11 дней **учёба — это и есть «продукт», а приложение — маленький аид**. Поэтому план реорганизован: в центре — **ежедневный протокол учёбы (§1), независимый от приложения**; приложение строим **только там, где оно даёт пользу быстрее, чем эквивалентная учёба** (§3), и только после дневной нормы учёбы (§2).

---

## 1. Ежедневный протокол учёбы (НЕ требует приложения; стартует в день 0)
Это обязательная основа. Приложение её лишь усиливает.

| Навык | Ежедневно | Почему (доказательство) |
|---|---|---|
| **Аудирование** | **30–45 мин живого европейского PT** (подкасты/новости/TV/сериалы), фокус на смысл, не на слова | самая трудная секция; HVPT хочет сотни минут тренировки — копить с дня 0 (`EXAM_RESEARCH §B`, `LEARNING_SCIENCE §6`) |
| **Письмо** | 1 текст **70–90 слов** на тему матрицы (приветствие/связки/концовка, точный лимит) | Grupo IV = 50 б.; нужна продукция и точный объём |
| **Чтение** | 1 текст из livro/caderno + V/F-вопросы (на бумаге) | Grupo II |
| **Грамматика** | дриллы **слабых мест по результату mock** (род/артикль/предлоги в приоритете) | Grupo III = 50 б., зона провалов |
| **Mock** | **1 таймированный полный прогон каждые 2–3 дня** по вашей матрице/TESTE FINAL, ручной подсчёт по группам | формат/тайминг/диагностика; **«не обнули ни одну группу»** (per-section minimum) |

**Первый mock — в день 1** (бумага + ручной подсчёт), чтобы сразу увидеть слабые группы и нацелить дриллы. Не ждать приложения.

## 2. Правило «учёба до кода»
Сначала **≥2–3 ч учёбы по §1**, потом код. Если день занят — кодинг в этот день только «контент/справочник-уборка», без нового движка. Приложение НЕ должно съедать учебное время.

---

## 3. Приложение (строим, только если оправдывает себя против учёбы)
**Обязательная цель Фазы 1 = WP-A + WP-B** (+ протокол §1). **WP-C/D/E — stretch**: только после того, как WP-A/B готовы и первый mock (день 1) сделан, и только если не крадут учебное время. Порядок = приоритет.
**Платформенное требование первой реализации (SPEC §10.4), заложить в основу app сразу:** светлая/тёмная **тема** (по умолчанию системная, переключатель Авто/Светлая/Тёмная) и **локализация UI RU+EN** (по умолчанию системный язык, fallback на EN, если система не RU/EN). Тема — дёшево (CSS-переменные + `prefers-color-scheme`); i18n добавляет накладные расходы на вынос строк в `locales/{ru,en}.json` — учитывать в оценке WP-A/B.
**E2E-тесты — тоже требование первой реализации (SPEC §10.5):** Playwright-гейт E1–E6 (первый запуск · тема · локализация · офлайн · справочник · обновление SW) гоняется по собранному PWA с первой же WP-A/WP-B-сборки; `pnpm check` включает `e2e`. Заложить каркас `e2e/` сразу — учитывать в оценке WP-A/B.

### WP-A — «Exam Survival Kit» (одна страница) · S
Чек-лист 4 групп, ссылки на материалы, **таблица результатов mock по группам**, дневной план §1, предупреждение «не обнули группу». **БЕЗ обратного отсчёта дней** (повышает тревожность) — вместо него спокойный «фокус на сегодня». **`passThreshold`** — настройки `totalPassPoints` (из 200) и опц. `minGroupPoints` (из 50 на группу, модель 4×50 из SPEC §9.2), по умолчанию **`unknown`**. **Правило вердикта (однозначное):** как только задан **хотя бы один** порог — вердикт «сдаёт-риск» считается ТОЛЬКО по заданным порогам (незаданная сторона игнорируется, никогда не трактуется как провал); «сдаёт» = все заданные пороги выполнены. **Только когда не задан НИ один порог** (балл узнать у преподавателя — §9) — WP-A показывает **сырые баллы по группам + предупреждение «не обнули группу»**, без вердикта. **Done:** страница открывается офлайн, чек-лист и mock-таблица заполняются вручную. **Польза ★★★** (организует подготовку сразу, почти без кода).

### WP-B — Справочник (Reference) · M
Перечитываемые `referenceCard`: предлоги (de/em/a + контракции + **a casa/para casa** и исключения + деревья решений), артикли + подсказки-окончания рода, ser/estar, таблицы глаголов. Источник: `grammar_full` + `prepositions_teacher` + листы преподавателя. Статический рендер, без движка. **Done:** ≥6 карточек доступны офлайн. **Польза ★★★** (учиться сразу; «пологий вход»).

### WP-C — Дриллы рода/артикля + предлогов (production-first) · XL
Минимальный generative-движок (deterministic), **ввод/сборка**, **паритетные+правдоподобные дистракторы** (LS §3), фидбэк → deep-link в справочник, простая mastery (доля верных по под-навыку), кривая L1–L3. Режимы: **GenderArticle** (def+indef+контракции), **Preposition** (origem/local/tempo/movim./lugar). **Done:** оба играются по L1–L3 с production-вводом и верифиц. ключами; QA-семян зелёный. **Польза ★★★** (боли №1/№3, ядро Grupo III).

### WP-D — Mock-shell с ручным вводом · M
Экран прогона: таймер 90 мин, без подсказок; **ответы/баллы по группам вводятся вручную** (итены берутся из матрицы/TESTE FINAL/листов); сохранение в таблицу WP-A; правило минимума по группе. (НЕ авто-генерация всех итенов — это позже.) **Done:** можно провести таймированный mock и увидеть счёт по 4 группам. **Польза ★★★** (диагностика + тренировка формата).

### WP-E — Минимальный лог + экспорт · S
`attempts/sessions` в localStorage/IndexedDB + кнопка **JSON-экспорт** (+ `navigator.share`). **WP-E — stretch;** если строится — в его объём входит **restore (восстановление своего состояния из бандла)**; **merge** нескольких пользователей — вне Фазы 1 (SPEC §13.3). **Done (когда WP-E построен):** решённые задачи логируются, экспорт даёт валидный JSON, **импорт восстанавливает состояние** (SPEC §10.2 условный тест #5). **Польза ★** (анализ позже).

> **Обязательная цель — только WP-A + WP-B.** WP-C/D/E и §4 — stretch, строго после §1 и готовых WP-A/B.

## 4. Опционально / если останется время (вторично)
- **Listening HVPT в приложении** — **расцеплено** от движка дриллов (просто: аудио-ассет + подпись-варианты + кнопка повтора + ключ). Строить ТОЛЬКО если генерация аудио тривиальна; иначе — §1 (живое аудио). HVPT-формат: identification, орфо-метки, 4–6 «голосов», минимальные пары EP-редукции.
- Остаток Grupo III: ser/estar, conjugation, numbers (cardinais+ordinais) — **топ-3 по частоте**; pronoun/demonstrative/possessive — в справочник/на бумагу, если mock не покажет слабость.
- Vocabulary (FSRS, production: артикль+слово/cloze, 5–7×≥3) + Intruso.
- Reading в приложении (≥3 текста с ключами), Writing в приложении (5 промптов + счётчик + чек-лист).
- Полная телеметрия/дашборд-аналитика/**полный** контент-пайплайн с миграциями/PWA-обновления — **после экзамена** (полный SPEC). *(Это НЕ исключает **минимального** build-content шага для WP-B: `extraction/normalized → public/content.vN.json → IndexedDB` — загрузка по `contentVersion` с version-bump, alias-таблицей переименований и обработкой orphaned-progress (как строит и тестирует DEV_LOOP_PLAN T6, SPEC §7.3); **БЕЗ** полного набора миграций сверх version-bump и **БЕЗ** PWA-обновлений контента. Нужен уже в Фазе 1 для справочных карточек. Откладывается именно полный пайплайн с расширенными миграциями и авто-обновлениями контента через PWA.)*

## 5. Честные размеры и порядок отказа
- Размеры (честно): WP-A **S**, WP-B **M**, WP-C **XL**, WP-D **M**, WP-E **S**. §4 — каждый L–XL.
- **Минимально-жизнеспособный аид = WP-A + WP-B** (+ §1). Если время позволит — WP-C, затем WP-D, затем WP-E.
- **Порядок отказа (режем с конца §4 к началу):** полная телеметрия → reading/writing/vocab в приложении → Listening HVPT в приложении (оставить живое аудио §1) → остаток Grupo III (на бумагу) → WP-E → WP-D (вести mock-счёт на бумаге) → WP-C (дриллы на бумаге/в справочнике) → **неснижаемый минимум: WP-A + WP-B + протокол §1**.

## 6. Definition of Done — Фаза 1 (со счётными порогами)
**Обязательно (это и есть «Фаза 1 готова»):**
- §1 идёт ежедневно с дня 0; первый mock сделан в день 1.
- WP-A: страница-кит работает офлайн; mock-таблица ведётся.
- WP-B: ≥6 справочных карточек.
- **Тема** (Авто/Светлая/Тёмная, по умолчанию системная) и **локализация UI RU+EN** заложены в первую же app-сборку (WP-A/WP-B) — SPEC §10.4.
- **E2E-гейт E1–E6 зелёный** (Playwright по собранному PWA: первый запуск · тема · локализация · офлайн · справочник · обновление SW) — SPEC §10.5; `pnpm check` проходит (typecheck+lint+unit+build+e2e — build перед e2e, т.к. E2E идут по `dist/`).
- **Cutover-провизии заложены в первую сборку (SPEC §10.6):** проверяемые на этапе сборки WP-A/WP-B — IndexedDB v2 = отдельная база `lingvago2` (база v1 `lingvago` не тронута) и manifest сконфигурирован с `scope='/'`/`start_url='/'`. **Сам деплой на тот же origin (авто-обновление установленного ярлыка) и вывод v1 в обязательный DoD НЕ входят** — требуют подтверждённого хостинга/URL и фактического same-origin-деплоя, см. отдельный гейт ниже.

**Stretch (засчитывается, только если построено; НЕ блокирует «Фаза 1 готова»):**
- WP-C: GenderArticle и Preposition играются L1–L3, production-ввод, верифиц. ключи, фидбэк→справочник.
- WP-D: ≥1 полный таймированный mock со счётом по 4 группам.
- WP-E: лог + JSON-экспорт + импорт/restore.

**Гейт замены v1 (ПОСЛЕ Фазы 1 — не входит в обязательный DoD; SPEC §10.6):** фактический cutover/вывод v1 требует **деплоя v2 на тот же origin/`scope=/`** (установленный PWA-ярлык авто-обновляется), чтобы перенесённые **NumbersMode/ConjugationMode** (SPEC §1.2 — stretch) были подтверждены рабочими в v2, плюс зелёные E2E E1–E6 и ручная офлайн-проверка на телефоне. Поскольку режимы — stretch, замена v1 происходит только когда они построены; до тех пор v1 остаётся (базы `lingvago`/`lingvago2` сосуществуют, откат возможен).

**Везде — честность статусов:** Listening/Reading/Writing в приложении помечены «не экзамен-эквивалентно», пока не выполнены счётные минимумы (Listening — ≥20 аудио-итенов или нулевая готовность; Reading — ≥3 текста с ключами; Writing — ≥5 промптов; GIII-mock — ≥25 верифиц. итенов).

## 7. Риски (что план мог недооценить)
- **Аудирование** — самый большой реальный риск к экзамену; митигиция в §1 (живое аудио ежедневно с дня 0), не в коде.
- **Build съедает study** — митигиция §2 (учёба до кода).
- **Неверные ключи** хуже отсутствия фичи → QA-семян (SPEC §6.5) до показа в mock.
- **Переоценка скорости сборки** — размеры честные (§5), ядро мало.
